# apay (Aura Pay)

UPI-style, mobile-first web app for sending "aura" (✦) to friends. Next.js 15 App Router + Tailwind v4 + Neon Postgres (`@neondatabase/serverless`). See README.md for features and layout.

## Conventions
- Mobile-first UI, clean and minimal. Colors are CSS tokens in `src/app/globals.css` (`bg-bg`, `bg-surface`, `text-ink`, `text-muted`, `border-line`, `bg-accent`, ...) Light is the default; dark tokens apply only under `<html data-theme="dark">` (not OS preference). Use these, not raw colors.
- Aura amounts are whole integers. New users start with 1000.
- Aura ID = `handle` column; display as `handle@aura` via `auraId()` in `src/lib/validate.ts`. URLs use the bare handle (`/chat/[handle]`).
- Multiple Aura IDs: `aura_ids` holds every ID (including the main `users.handle`), max 3 per user; its PK keeps IDs unique across accounts. Look users up with `getUserByHandle()` (resolves any ID, returns the main handle). Signup inserts the user and its `aura_ids` row in one statement. `/chat/<extra-id>` redirects to the main ID.
- Profile (`/profile`, linked from the top of `HomeMenu`): change name, add/remove/make-main Aura IDs, change password, change/create Aura PIN (`/api/pin/change` verifies the current PIN via `checkPin`).
- Profile pictures: `users.avatar_url` holds a public Vercel Blob URL (`BLOB_READ_WRITE_TOKEN`, one store shared by dev and prod). The browser center-crops and shrinks to 256px WebP/JPEG (`squareImage()` in `src/lib/client.ts`) and POSTs the raw image to `/api/profile/avatar` (DELETE removes); the route checks file signatures and deletes the replaced blob in `after()`. Pass `src={avatarUrl}` to `<Avatar>`; it falls back to initials.
- Auth: JWT in httpOnly cookie `apay_session` (`src/lib/token.ts`, `src/lib/session.ts`); `src/middleware.ts` guards pages. API routes call `currentUserId()` themselves.
- 4-digit Aura PIN, bcrypt-hashed, checked via `checkPin()` (5 wrong → 5-min lock). Balance is only returned by `POST /api/balance` with a PIN.
- Transfers are one atomic SQL statement in `transferAura()` (`src/lib/queries.ts`). Keep it that way.
- Aura tax (`src/lib/tax.ts`, shared by client and server): transfers >= 10,000 pay 1% (up to 9,999 is tax-free) of the whole amount (floored). Sender is debited `amount`, receiver credited `amount - tax`; `messages.tax` records it. The pay sheet shows a warning and needs a second tap before the PIN.
- Leagues (`src/lib/league.ts`): Rookie 0, Seeker 5k, Farmer 10k, Master 100k, Overlord 500k, God 1M (each "or more"). Home page passes `leagueStatus()` (league + aura to next, not the raw balance) to `LeagueBadge` next to the name; tapping it opens the ladder sheet. Colors are `--league-*` tokens.
- `users.verified`: set manually in the DB, or bought at `/profile/verify` (linked from the end of `/profile`): profile photo, address, occupation (employed/salaried/student), monthly income (₹), then PIN. `buyVerification()` debits `VERIFY_FEE` (24,999, `src/lib/verification.ts`), sets `verified` and saves the details to `verifications` in one statement; the fee is not transferred to anyone. Render names with `<VerifiedName>` (`src/components/VerifiedName.tsx`) so the badge shows.
- Schema changes: add `ALTER TABLE ... IF NOT EXISTS` lines to `db/schema.sql` (it's re-run by `db:migrate`).
- Push notifications: `web-push` with VAPID keys from env. Server sends via `notifyUser()` (`src/lib/push.ts`) inside `after()` in the chat and pay routes; never let push failures fail a request. Service worker is `public/sw.js` (skips the notification if that chat is focused). Browser side is `src/lib/pushClient.ts`; `NotificationPrompt` on home asks permission; logout unsubscribes the device.
- Quick actions under the balance (`QuickActions`): Scan (`ScanSheet`, camera + `jsqr`), Receive (`ReceiveSheet`, `qrcode`), History (`/history`, `listPayments()`), Aura Loan (`/loans`, see below). Receive QRs encode `payLink()` = `<origin>/chat/<handle>?pay=1` (`src/lib/qr.ts`); `?pay=1` opens the pay sheet in `ChatView`.
- Aura Loan (`/loans`): tabs Available / Pending / Ongoing / Closed. Banks are rows in the `banks` table (`listBanks()`/`getBank()`; hidden ones have `active = false`). Rules/maths live in `src/lib/loans.ts` (shared client/server): amount is picked from 100/75/50/25/10% of min(bank `upTo`, 10x balance) rounded down to 100; fees 6% aura tax + 2% processing + 1% GST + 1% platform are taken from the payout (`received`); simple monthly interest; repaid in weekly EMIs (4 per month of tenure, last EMI absorbs rounding). Verified account needed if amount > 50,000 or tenure > 3 months. Apply needs the pledge checkbox (Terms & conditions sheet in `LoansView`). One pending/ongoing loan per bank (partial unique index).
- Loan lifecycle is lazy: `settleLoans(me)` (`src/lib/queries.ts`) approves pending loans whose `approve_at` (apply + 2 min) has passed and credits `received`, then charges every due weekly EMI and closes repaid loans. Call it before anything reads or spends the balance (home, `/loans`, `GET /api/loans`, `/api/balance`, `/api/pay`, `/api/verify`). `POST /api/loans/[id]/instant` (PIN) approves now for 5% of the amount; `DELETE /api/loans/[id]` cancels a still-pending loan (row deleted, no aura has moved). EMIs can make the balance negative: the `users.balance >= 0` CHECK is dropped, so anything that spends aura must check the balance in its own SQL (`transferAura`, `buyVerification` do).
- Aura betting (Earn aura): best-of-3 tic-tac-toe for a stake. Rules are pure functions in `src/lib/bet.ts` (`playMove`, `timeOut`, `forfeit` return the next `Game` + payouts); the server applies them via `applyToBet()`/`commitStep()` in `queries.ts`, which writes only if `bets.version` is unchanged and pays out in the same statement. Challenger X, opponent O, starter alternates; first to 2 round wins takes 2x stake; tied after 3 rounds = both stakes back; 60s per move (lazy: `getBet()` applies a timed-out turn as a lost round); "Give up" forfeits the pot. Stakes are taken on commit: `createBet()` (challenge, PIN) also inserts a `kind = 'bet'` chat message; `acceptBet()` (PIN) takes the opponent's; decline/cancel refunds (`withdrawBet()`). Entry points: `EarnAura` card on home (open games + friend picker) and the swords button in the chat composer, both open `ChallengeSheet`. Game page `/bet/[id]` (`BetView`) polls `GET /api/bets/[id]` every 1.5s; `POST /api/bets/[id]` takes `{ action: accept|decline|cancel|move|forfeit }`. Chat polls return `bets` so challenge cards (`BetBubble`) stay live.
- Admin (`/admin`, not linked anywhere): no user login, unlocked by the static PIN in `src/lib/admin.ts` (server-only; 5 wrong attempts across everyone lock it for 5 min via `admin_lock`). Sets a 12h httpOnly `apay_admin` cookie (JWT with subject "admin"); `src/middleware.ts` lets `/admin` through without a session, and every `/api/admin/*` route checks `isAdmin()`. Manages banks: add, edit name/interest/limit/tenure, verified badge, show/hide, logo (`/api/admin/banks/[id]/logo`). Image uploads (avatars, logos) share `storeImage()`/`deleteImageLater()` in `src/lib/images.ts`.
- Home menu (`HomeMenu`, hamburger top-right) holds a Notifications on/off switch (`pushStatus`/`enablePush`/`disablePush`) and Sign out. The home `NotificationPrompt` card is temporarily commented out in `src/app/page.tsx`.
- Chat: text and payments share the `messages` table; client polls `GET /api/chat/[handle]?after=<id>` every 3s.
- Unread: `chat_reads.last_read_id` per (user, friend); opening a chat and polls that return their messages call `markRead()`. `listFriends()` returns `unread`; `FriendsGrid` shows a blue dot.
- Typing / paying: `chat_activity` heartbeat. `ChatView` POSTs `/api/chat/[handle]/activity` every 2.5s while typing (4s idle cutoff) or while the pay/PIN sheet is open; entries expire after 6s. The chat poll returns the friend's `activity`, shown under their name. Sending a message or payment clears it.
